G4 Section 2 permits PREEXCLUDED_UNAVAILABLE_REQUIRED_SOURCE before outcome
scoring. These clauses must be interpreted together, not opportunistically.

In v2, the public registered action is MERGE_PR by an
ORDINARY_NON_BYPASS_MERGER. Observed approvals make reviewer permission
unavailable with the lawful app; 10/25 selected rows were excluded. The
public scorable evidence is all BLOCKED because the approval requirement is
unsatisfied. The positive class comes only from a separate controlled repo
with no governance rules. Thus the experiment tests a restricted domain
whose broad approval/permission and bypass histories remain unobserved.

A lawful pre-outcome exclusion prevents fabricated native labels. It does
NOT by itself prove representation/decision completeness on the excluded
reachable histories. Whether this suffices for the original intended G6
coverage gate depends on what a 'registered family' and its C1 every-history
quantifier allowed at initial freeze. The new v2 pass condition is a
pre-native, prospective development rule, not an amendment retroactively
overriding the G4 quantifier.

Potential additional validity question: native PR mergeable_state comes from
GitHub's server-side governance computation, not an explicitly actor-specific
ordinary-merger oracle. This actor alignment requires independent validation
before full actor-class equivalence is claimed.
