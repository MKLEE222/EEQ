## 1. Stop mixing two distinct meanings of B9

**B9-v1 FROZEN** is `protocol-native hand-engineered sufficient state` as defined in `parityplus/g4/UNIFIED_PROTOCOL_FREEZE_v1.md` blob `3eeaeeb828d2fcf7ec4487da06489fee3146c920`. Under G4, a representation receives an ORACLE-OPTIMAL deterministic decoder over its exact observed equivalence classes. B9-v1 is a concrete representation; it need not be equivalent to an unrestricted set of all possible computable algorithms.

**B9-full-strong RESEARCH ADVERSARY** is a separately reported fairness comparator in E1/E2/P2: a domain engineer with the SAME legitimate native inputs, trust roots, permission to query, provenance, crypto and native libraries, standard completeness/Reflector/cut/IVM tools, and permission to build any proof or evidence construction using those tools. If one defines it literally as *all possible algorithms including EEQ*, universal strict expressivity dominance of that set is impossible by set inclusion; this tautology must NOT be confused with a measured experiment against the frozen B9-v1 or a concrete fixed engineered baseline.

Scientific benefit must be formulated with a precisely frozen **implementable, full-strength alternative** on newly specified contracts/native changes, not an unbounded oracle that can redefine itself in retrospect. Any new B9-full implementation must itself be preregistered before the tasks/results, with equivalent source access and code reuse rights. Historical negative ties remain.

## 2. Trust accounting is set-valued, not merely a code line count

Actual P2's portable `verify(program, external)` is 66 source lines, but trusts the 146-line TUF and 162-line K8s source-witness construction procedures, the underlying cryptographic/canonicalization/native semantics, the GitHub artifact/workflow provenance, and each domain's externally supplied source inventory and epoch. There is no evidence the *end-to-end* TCB became smaller than a fully informed native B9 implementation. Counting the 66-line function alone would be a false comparison.

TCB transparency can be stated as an **obligation graph**:
- `decision_claim <- complete declared contract and universe`
- `proof_ast <- trusted native predicate source entailment`
- `native predicate <- parser, validation grammar, native action semantics`
- `current warrant <- actor credentials + contemporaneous time-bound source coverage`
- `source identity <- authenticated original source custody + SHA`
- `verification result <- checker + justified witness-generation/custody provenance`

A claim of a smaller trusted base must specify which of these nodes become *untrusted and independently verified*, by WHAT trusted primitive, and quantify any new witness generator/checker surface that replaces them. Merely transferring a check to another handwritten module does NOT shrink TCB.

## 3. No-go statement prior to any next feature implementation

There is NO semantic oracle that can infer a foreign native format's arbitrary true meaning from identical bytes without a versioned, trusted interpreter/semantics description. For two possible native environments interpreting the same observed bytes differently, any source-bytes-only rule extractor must produce the same answer for both although their correct contract results differ. It follows that a new environment always entails at least a trusted versioned semantic mapping or native attestation. This is elementary observational indistinguishability, not EEQ novelty.

There is NO uniquely defined minimal source-support set in general; alternative sufficient branches create incomparable minimal witnesses and an explicit antichain can have exponential size. Specify a target cost/ordering and whether a symbolic representation of support is allowed.

There is NO sound global negative source claim without a credible bound on what source kinds/actors/time points could contribute: unreadable old Deny, unregistered new Binding, or disconnected cross-kind observations can keep opposite-effect worlds observationally identical.

## 4. Precise CONDITIONAL GO hypothesis for the next stage (not demonstrated)

For a PREDECLARED class `G` of supported native source grammars, a `R` of externally anchored trust assumptions, and an independently authored change set `Delta`:

An EEQ proof-construction procedure `C` should generate a tuple `(Q,P,V,A)`:
- `Q`: explicit native-qualified source queries, lawful actor and bounded time/snapshot authority.
- `P`: certificate whose primitive proof obligations have real source provenance.
- `V`: a small, independently executable source-entailment checker that does NOT trust the same unverified Boolean leaves as producer.
- `A`: all external assumptions, including any completeness, trust-root or actor claims that still lack a native attestation. If they are not available, the result must refuse and specify the needed obligation.

Against an implementable FULL-STRENGTH B9 alternative using identical native clients, provenance, crypto, cached sources, known proof techniques and equivalent risk/coverage targets, test whether EEQ reduces fully-charged *new* domain-semantic translation and maintenance work under previously UNSEEN semantically material deltas. Correctness and non-inferiority of refusal/coverage are independent mandatory gates. A speed or sample-count win alone does not meet H3.

**Required separate measurements (none have been produced):**
1. Independently specified feature/change tasks and legally obtainable raw sources, frozen before both implementations.
2. All code and verification work: grammar/parser integration; source-set enumeration; authority/actor/time/complete-roster acquisition; native oracle setup; IR/witness generator; checker; tests, debugging and failed attempts; operational maintenance.
3. Primary estimator: verified scoped obligations correctly supported or correctly refused per TOTAL independently observed adaptation labor, with paired/counterbalanced qualified maintainers or another independent auditable experimental allocation. Record raw minutes and confidence/variance, NOT cherry-picked examples or author self-timing.
4. Full B9 access to existing native interpreters/Reflector, lineage/IVM and the same certificate representation/checker, and pre-registered use of reusable code. No deliberate baseline handicap.
5. Independent native oracle with explicit authority/clock/scope, not replaying E2/P2 development labels as fresh outcomes. Preserve all failure denominators.
6. Scientifically realistic claim: method/tool CONSTRUCTION advantage relative to a fixed strong implementation under these budgets; never blanket expressivity superiority over 'all possible algorithms'.

No independent maintainers/trial currently exist. In their absence, a source-to-obligation translation validation proof on a restricted grammar and source-to-source equivalence checks may still be valuable **development diagnostics** but cannot be scored as demonstrated P3 advantage.

## 5. Decision rule

**NO-GO THEORY:** proposed novelty is `proof tree + source hashes`, `least complete source set`, `dynamic proof cache`, `lawful query tree`, `qualified post-action observation` or `consistent cut` alone. They already have strong known counterparts. Do not spend another round on renamed abstractions.

**NO-GO PORTABILITY:** third domain or changed native semantics requires a new interpreter/parser of nearly all source/policy semantics while shared checker remains only Boolean AST equality, and there is no independent comparison demonstrating saved trusted work.

**GO FOR CONDITIONAL SYSTEMS-METHOD RESEARCH:** a genuinely smaller or more independently checked producer-specific trusted base and/or a demonstrably reusable obligation extraction interface, with explicit native trust premises, preserved native correctness, safe refusal, and fair externally audited constructibility advantage over a fixed fully informed baseline.

**GO FOR NEW THEORY:** only an exact semantic-preservation gap in existing completeness/trust-management/PCC/DEL/distributed cut frameworks plus a nontrivial independently reviewed proof, with a proper statement of finite/decidable/asymptotic conditions. The K0 audit did NOT find one.

**STOP:** if no independent reduction gap and no believable measurable P3 advantage, position EEQ as a rigorous multi-domain evidence/safety systems framework; do not assert a foundational new algebra merely to fill a novelty narrative.
