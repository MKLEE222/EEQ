## 1. Mother question

A system's actions change which future information remains valid, which
sources can lawfully support a specified claim, which distinctions must
survive, and which later decisions therefore have sufficient evidence.

Chinese formulation:
系统的动作会改变以后哪些信息仍然有效、哪些来源仍有资格支持指定主张、
哪些区分必须保留，以及由此哪些后续决策有依据。

We do not define success as another 1.0 oracle-optimal accuracy result.
The scientific question is whether we can construct and check these
distinctions from **lawful native evidence and executable action semantics**
without being handed a fully annotated state graph or the desired label.

## 2. Three potentially falsifiable hypotheses

**H1 / lawful native construction.** Starting from registered source bytes,
authority/qualification rules and native actions, a fixed, label-blind
extractor can produce an evidence-state successor model with an auditable
coverage/refusal boundary. This includes provenance, claim binding and
continuation, not just a state dictionary chosen by an expert.

**H2 / bidirectional distinction necessity.** In real native histories:
(A) two states may have the same presently permitted decisions yet diverge
under a registered later action; their difference must be retained, with a
native-verifiable separating action word;
(B) two states with genuinely different lawful evidence/qualification/history
may nevertheless be equivalent for *all* registered future decisions at the
declared horizon; their differences can be legitimately erased. Cosmetic JSON
or Suite/Version perturbations alone do not satisfy (B).

**H3 / independent benefit relative to strong alternatives.** When H1/H2
are satisfied, the overall compiler+certificate workflow must create
nontrivial value compared with B9 (protocol-native hand-engineered sufficient
state) and a conventional exact quotient of the SAME lawful state graph.
Possible dimensions: lawful construction/maintenance labor across families,
refusal soundness at matched decision coverage, checked evidence-source
certificates, downstream correction/audit path fidelity, and fully charged
storage/latency. No advantage is presumed in any dimension.

These hypotheses are conjunctive for a general native-method claim. An H1/H2
success without a fair H3 win is **valuable feasibility, not unique novelty**.

## 3. What is NOT novel

Moore / Paige-Tarjan partition refinement, finite-horizon trace equivalence,
automaton minimization, three-valued UNKNOWN/REFUSE, ordinary provenance
recording, and native hand-written sufficient-state construction are prior
techniques. If the new contribution reduces to "run standard minimization
on an already supplied graph", stop the method-novelty claim.

The mathematical lemma describing the coarsest contract-relative partition
is a correctness statement, not a novelty claim.

## 5. Sequential experimental logic

**R0: hard question and admissibility (this charter).** Freeze hypotheses,
negative results, source-access rules and baseline fairness *before* selecting
new evidence. Literature threat ledger must include standard refinement and
strong native sufficient states.

**R1: native extractor feasibility, TUF development.** Begin with pinned
Bottlerocket root-update semantics, because a real ordered trust chain and
root-key authorization system exist. Freeze before new execution: exact
native version, source IDs/bytes, action grammar, transition semantics,
qualification predicates and fail-closed boundary. This phase does not claim
TUF can already supply multi-support or nontrivial merges.

**R2: first native A/B pair.** Predeclare both counterfactuals (and at least
one material UNKNOWN/REFUSE situation) *before* reading their new native
outcomes. Use a separate direct native oracle, never an outcome-derived
successor table. Failure remains visible; do not substitute a winning pair.

**R3: independent multi-support native mechanism.** Use Kubernetes
admission-policy/binding continuation as development candidate **only if**
source/claim-binding changes and policy-update actions can be implemented and
observed lawfully. If it cannot provide a complete registered successor
boundary, report C3_UNSUPPORTED instead of manufacturing transitions.

**R4: fair baseline challenge.** Compare the native model extractor and
certifier against B0, B9, v1 B10, an equally informed classical quotient and
all structurally applicable original omissions. Report each axis separately;
do not combine incomparable cases into one accuracy denominator.

**R5: prospective transfer.** Only after R1-R4 warrant a general method
claim, freeze a fresh protocol version and select a NEW untouched family.
Do not choose it after observing whether the candidate works there.

No R1-R5 item may be declared PASS merely because a CI workflow exits zero.

## 6. Scientific kill rules

K0 — No lawful, outcome-blind native transition extractor can be built over
the registered source/action subset: mark EXTRACTOR_NOT_ESTABLISHED. Finite
synthetic quotient results remain finite-only.

K1 — No real A contrast exists under preregistered action/contract scope:
future-distinction utility NOT DEMONSTRATED. Do not widen r or change actions
after scoring without a newly versioned experiment.

K2 — No real non-cosmetic B contrast exists with exhaustive registered
future-action checking: nontrivial quotient compression NOT DEMONSTRATED.
Metadata reserialization does not count.

K3 — B9 and conventional quotient attain identical legal-task fidelity and
no independently measured construction/certification/coverage-cost advantage
survives: label the result **B9_TIE / NO_INDEPENDENT_VALUE**. Do not remove B9.

K4 — Source/qualification/claim-binding needed for a conclusion is
unavailable: return REFUSE / UNSUPPORTED with the explicit coverage boundary.
Unknown must never be silently interpreted as false or as evidence-free
permission.

K5 — Any core/schema change while scoring under frozen G4-v1: record a
PROTOCOL_BREAK and leave the older scores untouched.

No "post-hoc rescue" by changing the native action vocabulary, eligible
population, semantic case ID, comparator input information, horizon,
confidence measure or task definition.

## 7. Primary evaluation dimensions

For each registered native family and contract:
- lawful evidence acquisition coverage and missing-source / actor boundary;
- state graph closure over declared histories and registered actions;
- false permissions, false refusals, exact continuation action-set/path
  recovery, case-level native matches and uncertainty outcomes;
- A separating certificates verified by native future execution;
- B merged **genuinely different** lawful evidence states, independently
  verified over every registered action path up to r;
- B9 and conventional quotient with identical lawful inputs and action scope;
- full costs: acquisition, preprocessing, hand-engineering effort,
  transition extraction, compilation, class ID/codebook, retained evidence,
  certificate verification, downstream query latency, peak RSS;
- version/actor/authorization perturbation classes and refusal calibration.

Within-grid oracle-optimal decoder is diagnostic, NOT held-out generalization.
Where B9 reaches 100% accuracy, scoring accuracy cannot strictly beat it;
look for independent value or report a tie.
