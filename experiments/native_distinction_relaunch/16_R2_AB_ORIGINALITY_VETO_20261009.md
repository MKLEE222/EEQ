## Strongest prior-art/semantic reduction threats

1. **Standard quotient threat (R2B).** For a contract that excludes
   targets-role verification, keeping only a sufficient root-update
   state is standard domain projection. Moore refinement performs the
   legal merge exactly as proposed new quotient. Authentic targets-role
   differences make it NONCOSMETIC, but do not make the quotient operator new.

2. **Obvious rule-evaluation threat (R2A).** Binding A checks team=tenant;
   binding B checks team=tenant AND mode=strict. Changing mode from strict
   to relaxed predictably changes applicability under ordinary
   Kubernetes native admission matching. Even native A success would
   demonstrate mechanism observability and lawful source-to-state
   extraction, not a new admission algorithm or new causal theorem.

3. **Fully informed B9 threat (both).** Under identical source, rules and
   future action conditions, a domain expert B9 can preserve root version,
   key roles, namespace labels, binding selectors and CEL predicates.
   It can reproduce BOTH contrasts. A "zero current-only baseline"
   that ignores these variables is useful as a diagnostic but cannot
   be called the strongest competing representation.

4. **Hand-written adapter threat.** R2B and R2A each require a
   family-specific script that understands exactly the relevant native
   schema. The research has NOT shown a generic, lawful, label-blind
   source-to-transition compiler under stable semantics across
   different native policy ecosystems.

5. **Certificate triviality threat.** A script printing signer keyids or
   namespace resourceVersions is a useful audit trail, but NOT evidence
   of a novel verification scheme unless the certificate is independently
   checked and beats or provides capabilities absent from a FAIR
   information-equivalent baseline.

6. **Controlled-carrier bias.** Every new R2A/R2B fixture was constructed
   to expose its intended contrast. It provides diagnostic evidence of
   existence under native semantics, NOT production prevalence, unbiased
   transfer or observed real-world performance.

## What could make a real H3 contribution later

Pre-register one primary metric before any general method scoring, chosen
from the existing R0 charter:
- P1: better safe native decision COVERAGE for the same false permission
  bound and lawful accessible evidence;
- P2: smaller TOTAL retrieval+extraction+certificate+codebook+evaluation
  cost with matched exact native downstream decisions;
- P3: measurably lower future-family domain-specific maintenance labor
  under a predetermined, independently audited adaptation task;
- P4: independently verifiable source/claim/qualification/transition
  certificates which an equally informed expert B9 cannot offer with
  the same cost/guarantees.

A successful controlled R2B merge or R2A native future split by itself
satisfies NONE of these superiority requirements.

The next serious method experiment must test a reusable source-to-model
construction/certification process on >1 independent native source
family WITHOUT manually handing it complete successor graphs, with
unavailable-source/REFUSE boundaries and an unmodified strong B9.

This veto survives whether the R2A Kind workflow passes or fails.
